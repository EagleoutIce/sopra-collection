\section{General}
\subsection{Why, wherefore, what for?}
    This \LaTeXe package was written as part of the Sopra in the
    2019 winter semester and 2020 summer semester and serves as the
    foundation for creating documentation for the other packages and classes
    of \imptext{Team 20}, which are created together with
    \T{sopra-base.cls}.\par
    To visualize the individual code excerpts, the
    \T{sopra-listings} package is used. It is not relevant for the use of the package (\jmark[\T{nolistings}]{mrk:nolistings}).\par
    The associated package should also be embedded in this document: \scalebox{0.65}{\attachfile[subject={sopra-documentation.sty}]{sopra-documentation.sty}}.
\subsection{Dependencies}
    This package includes the following packages:
    \begin{multicols}{3}
        \begin{itemize}
            \def\pkgparse#1:#2\@nil{%
                \T{#1}\ifx!#2!\else\textsuperscript{(#2)}\fi%
            }
            \foreach \pkg in {xcolor:,attachfile2:,multicol:,sopra-listings:{only \jmark[\T{listings}]{mrk:listings}},blindtext:{only \jmark[\T{dummy}]{mrk:dummy}},
                hyperref:} {
                \item \expandafter\pkgparse\pkg\@nil
            }
        \end{itemize}
    \end{multicols}
    All of these packages should be part of the common \LaTeX{} distribution or shipped alongside it.

\subsection{Installation}
    The package is not shipped as a \T{.dtx}, which is why the
    following options are available:
    \begin{itemize}
        \item The package can be placed in the same directory as the
                document. In this case, the inclusion instruction is:
\begin{plainlatex}
\usepackage{sopra-documentation}
\end{plainlatex}
        \item The package can be placed in a subdirectory/in a
                directory shipped with the document. In this case, it is
                specified via the (relative) path:
\begin{plainlatex}
\usepackage{./My/Path/to/sopra-documentation}
\end{plainlatex}
        \item One can place the package (via a symlink or similar)
              into one's own \emph{texmf} tree.
              For example, on Linux using texlive, the package can be
              placed here: \bvoid{\~/texmf/tex/latex/}.
              The directory can be created and subsequently updated via
              \bbash{texhash \~/texmf}. Now the package can be used like
              any other installed package:
\begin{plainlatex}
\usepackage{sopra-documentation}
\end{plainlatex}
    \end{itemize}

\section{Package configuration}
    \subsection{Accepted parameters}
    Like most, the package accepts arguments.
    For arguments with a \say{counter} option, the one active by default is written first and the other in brackets.
    So implicitly:
\begin{plainlatex}
    \usepackage[nodebug,dummy,listings]{sopra-documentation}
\end{plainlatex}
    is invoked. Whereas with:
\begin{plainlatex}
    \usepackage[nolistings]{sopra-documentation}
\end{plainlatex}
    we compile the document without the \T{LILLYxLISTINGS} package.

    \begin{argument}{nodebug}{debug}
        \label{mrk:debug}In \T{debug} mode, the log is made more verbose thanks to \cmd{errorcontextlines} (in case of an error).
    \end{argument}

    \begin{argument}{dummy}{nodummy}
        \label{mrk:nodummy}In \T{dummy} mode, the \T{blindtext} package is included, otherwise not.
    \end{argument}

    \begin{argument}{listings}{nolistings}
        \label{mrk:nolistings}In \T{listings} mode, the \T{LILLYxLISTINGS} package is included, otherwise not.
    \end{argument}

\section{Commands and environments}

Note that the prefix \T{env@} only indicates the nature of an environment and is not to be considered part of the actual identifier!


\subsection{Compatibility mode}

\begin{center}
    \imptext{This mode is not available in \thesodversion{}!}
\end{center}

These commands are only defined with \jmark[\T{nolistings}]{mrk:nolistings}, since otherwise they would be included by \T{LILLYxLISTINGS}:

\begin{command}{T}{\manArg{Text}}
    Implemented here as an alias for \cmd{texttt}; sets \T{Text} in typewriter font.
\end{command}


\begin{command}{lstcomment}{\manArg{Text}}
    Similarly, \cmd{lstkwone}, \cmd{lstkwtwo}, \cmd{lstkwthree}, \cmd{lstkwfour}, \cmd{lstkwfive}, \cmd{lstkwsix}, \cmd{lststring} and \cmd{lstnumber} exist, which highlight \T{Text} in color.
\end{command}


\subsection{General commands}

\begin{command}{email}{\manArg{E-Mail}}
    Sets \T{E-Mail} as a clickable e-mail address.
\end{command}

\begin{command}{thesodversion}{}
    Returns the current version of the package. So \cmd{thesodversion} yields: \thesodversion\\
    \notetext{Note: via \blatex{\\value\{sodversion\}} the
    version can be obtained as a $4$-digit number: \arabic{sodversion}.}
\end{command}

\begin{command}{manArg}{\manArg{Text}}
    Allows a mandatory argument to be specified in \envref{command} or comparable environments. \notetext{For example, \T{Text} in the command definition is set using \cmd{manArg}!}
\end{command}

\begin{command}{optArg}{\manArg{Text}}
    Allows an optional argument to be specified in \envref{command} or comparable environments.
\end{command}

\begin{command}{cmd}{\manArg{Name}}
    Sets \T{Name} as a command: \T{\cmd{cmd}\{Hi\}}: \cmd{Hi}.
\end{command}

\begin{command}{env}{\manArg{Name}}
    Sets \T{Name} as an environment: \T{\cmd{env}\{Hi\}}: \env{Hi}.
\end{command}

\begin{command}{cmdref}{\manArg{Name}}
    Similar to \cmdref{cmd}, however (just as here) a link to the explanation of \T{Name} is created.
\end{command}

\begin{command}{envref}{\manArg{Name}}
    Similar to \cmdref{env}, however a link to the explanation of \T{Name} is created.
\end{command}

\begin{command}{argref}{\manArg{Name}\manArg{Counter}}
    Sets an argument with the corresponding counter option.
\end{command}


\begin{environment}{command}{\manArg{Name}\manArg{Arguments}}
    Starts the explanation of a new command with identifier \T{Name} (for \cmdref{cmdref}) and the arguments \T{Arguments}.
\end{environment}

\begin{environment}{environment}{\manArg{Name}\manArg{Arguments}}
    Starts the explanation of a new environment with identifier \T{Name} (for \cmdref{envref}) and the arguments \T{Arguments} (as here).
\end{environment}

\begin{environment}{argument}{\manArg{Name}\manArg{Counter-Name}}
    Starts the explanation of a new argument for the package/class with identifier \T{Name} and the counter identifier \T{Counter-Name}.
\end{environment}

\begin{command}{say}{\manArg{Text}}
    Sets \T{Text} in \say{quotation marks}.
\end{command}

\begin{command}{jmark}{\optArg{Text}\manArg{LinkTarget}}
    Works analogously to its counterpart in \T{Lilly}, because I like it better that way and write it out of reflex :D.
\end{command}

\subsection{Further commands}

These commands originate from the included packages and are merely configured here.

\begin{command}{attachfile}{\optArg{Options}\manArg{Path}}
    Embeds the file at \T{Path}. As \T{Options}, at least \T{subject} is worth using. For example, in this documentation the package is embedded with the following line:
\begin{plainlatex}
\attachfile[subject={sopra-documentation.sty}]{sopra-documentation.sty}
\end{plainlatex}
\end{command}

\begin{command}{textattachfile}{\optArg{Options}\manArg{Path}\manArg{Text}}
    Embeds the file at \T{Path}, but instead of a symbol makes \T{Text} the clickable link to open it. The options are analogous to \cmdref{attachfile}.
\end{command}

For all other methods used, it is recommended to take a closer look at the source code itself or the source code of the documentation.
